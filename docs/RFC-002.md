## 模块一：基于 Merkle DAG 的 AST 增量内容寻址存储（CAS 去重引擎）

### 1.1 设计目标与数学基础

目标：将快照落盘体积与 Git 历史膨胀降低 90%+，核心思路是把 JSON AST 的每一个子树都当作可寻址的不可变对象——只要子树内容不变，其哈希就不变，磁盘上就不会产生新的字节。

**后序遍历哈希推导。** 对 JSON AST 中的任意节点 `n`，定义其内容哈希函数 `H(n)`：

- **叶子节点**（`String`/`Number`/`Bool`/`Null`）：`H(leaf) = BLAKE3(tag_byte || canonical_bytes(leaf))`，其中 `tag_byte` 是区分类型的单字节判别符（防止 `"5"` 与数字 `5` 产生哈希碰撞），`canonical_bytes` 是该值的规范化序列化（数字采用固定精度的 IEEE-754 大端字节表示，字符串采用 UTF-8 原始字节，不做转义处理，避免转义方式不同导致哈希不稳定）。
- **数组节点**：`H(array) = BLAKE3(tag_ARRAY || len_le_u32 || H(child_0) || H(child_1) || ... || H(child_{n-1}))` —— 子哈希按数组原始顺序拼接，因为数组是有序容器，顺序本身是内容的一部分。
- **对象节点**：`H(object) = BLAKE3(tag_OBJECT || len_le_u32 || sorted_by_key[ (BLAKE3(key_bytes), H(value)) ])` —— 关键点是键值对必须先按键的字节序**排序**后再拼接哈希，这样对象哈希与原始 JSON 文本中的键顺序无关，天然对齐 RFC-001 中"对象比较按 Set 语义"的设计。

这是一个标准的自底向上（后序）递归：计算 `H(n)` 必须先递归计算完 `n` 的所有子节点的哈希。整棵树只需一次后序遍历即可得到根哈希，时间复杂度 `O(N)`，`N` 为节点总数。

### 1.2 完整数据结构定义

```rust
use blake3::Hash;
use serde::{Deserialize, Serialize};
use std::collections::HashMap;
use std::path::PathBuf;

/// 256 位内容哈希的强类型包装，避免与普通 [u8; 32] 混用出错。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct NodeHash(pub [u8; 32]);

impl NodeHash {
    pub fn from_blake3(h: Hash) -> Self {
        NodeHash(*h.as_bytes())
    }

    /// 用于磁盘分块目录布局：取前 2 字节十六进制作为分片目录，
    /// 避免单一目录下堆积百万级小文件导致的文件系统查找退化。
    pub fn shard_path(&self, root: &std::path::Path) -> PathBuf {
        let hex = hex::encode(self.0);
        root.join(&hex[0..2]).join(&hex[2..])
    }
}

/// AST 节点的 Merkle 化表示，替代裸 `serde_json::Value` 作为落盘单元。
/// 每个变体只存储"直接子节点的哈希"而非子节点本体，实现结构共享。
#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum MerkleNode {
    Null,
    Bool(bool),
    /// 存储原始规范化字节而非 f64，避免序列化精度损失导致哈希漂移。
    Number { canonical_bytes: Vec<u8> },
    String(String),
    Array { children: Vec<NodeHash> },
    /// 键已按字节序排序存储，与哈希计算顺序保持一致。
    Object { entries: Vec<(String, NodeHash)> },
}

/// 单个 CAS 对象在磁盘上的物理表示：内容寻址，键即是内容哈希。
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CasObject {
    pub hash: NodeHash,
    pub node: MerkleNode,
}

/// 内容寻址存储主体：负责建树、去重落盘、按哈希取回。
pub struct MerkleCasStore {
    /// CAS 对象根目录，例如 `__snapshots__/.cas/`。
    root_dir: PathBuf,
    /// 进程内 LRU 缓存，避免同一 CAS 运行中重复读盘反序列化。
    cache: HashMap<NodeHash, MerkleNode>,
}

/// 一个具名快照现在只需存储"根哈希 + 元数据"，AST 本体完全下沉到 CAS。
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct MerkleSnapshotPointer {
    pub endpoint_name: String,
    pub root_hash: NodeHash,
    pub metadata: crate::snapshot::SnapshotMetadata,
}
```

### 1.3 建树、子树哈希计算与分块去重落盘

```rust
use serde_json::Value;

impl MerkleCasStore {
    pub fn new(root_dir: PathBuf) -> std::io::Result<Self> {
        std::fs::create_dir_all(&root_dir)?;
        Ok(Self { root_dir, cache: HashMap::new() })
    }

    /// 递归建树：输入原始（已脱敏）JSON AST，输出根哈希；
    /// 沿途每个子树若尚未存在于 CAS 中，则写盘一次；已存在的子树直接复用，
    /// 这正是去重发生的地方——写盘调用次数等于"新增/变更子树数"，而非总节点数。
    pub fn ingest(&mut self, value: &Value) -> std::io::Result<NodeHash> {
        let node = match value {
            Value::Null => MerkleNode::Null,
            Value::Bool(b) => MerkleNode::Bool(*b),
            Value::Number(n) => MerkleNode::Number {
                canonical_bytes: canonicalize_number(n),
            },
            Value::String(s) => MerkleNode::String(s.clone()),
            Value::Array(arr) => {
                let mut children = Vec::with_capacity(arr.len());
                for elem in arr {
                    children.push(self.ingest(elem)?); // 后序：先递归子节点
                }
                MerkleNode::Array { children }
            }
            Value::Object(map) => {
                let mut entries: Vec<(String, NodeHash)> = Vec::with_capacity(map.len());
                for (k, v) in map {
                    entries.push((k.clone(), self.ingest(v)?)); // 后序：先递归子节点
                }
                entries.sort_by(|a, b| a.0.cmp(&b.0)); // 按键排序，见 1.1 数学定义
                MerkleNode::Object { entries }
            }
        };

        let hash = self.compute_hash(&node);
        self.write_if_absent(hash, &node)?;
        Ok(hash)
    }

    fn compute_hash(&self, node: &MerkleNode) -> NodeHash {
        let mut hasher = blake3::Hasher::new();
        match node {
            MerkleNode::Null => hasher.update(&[0u8]),
            MerkleNode::Bool(b) => hasher.update(&[1u8, *b as u8]),
            MerkleNode::Number { canonical_bytes } => {
                hasher.update(&[2u8]);
                hasher.update(canonical_bytes);
            }
            MerkleNode::String(s) => {
                hasher.update(&[3u8]);
                hasher.update(s.as_bytes());
            }
            MerkleNode::Array { children } => {
                hasher.update(&[4u8]);
                hasher.update(&(children.len() as u32).to_le_bytes());
                for child_hash in children {
                    hasher.update(&child_hash.0);
                }
            }
            MerkleNode::Object { entries } => {
                hasher.update(&[5u8]);
                hasher.update(&(entries.len() as u32).to_le_bytes());
                for (key, val_hash) in entries {
                    hasher.update(blake3::hash(key.as_bytes()).as_bytes());
                    hasher.update(&val_hash.0);
                }
            }
        };
        NodeHash::from_blake3(hasher.finalize())
    }

    /// 分块去重落盘：若目标哈希对应的文件已存在，直接跳过写入（这就是
    /// "去重"发生的物理层面——相同内容永远只占用一份磁盘 inode）。
    fn write_if_absent(&mut self, hash: NodeHash, node: &MerkleNode) -> std::io::Result<()> {
        if self.cache.contains_key(&hash) {
            return Ok(());
        }
        let path = hash.shard_path(&self.root_dir);
        if path.exists() {
            self.cache.insert(hash, node.clone());
            return Ok(());
        }
        std::fs::create_dir_all(path.parent().unwrap())?;
        let obj = CasObject { hash, node: node.clone() };
        let bytes = bincode::serialize(&obj).expect("MerkleNode serialization is infallible");
        // 原子写：先写临时文件再 rename，复用 RFC-001 §5.3 的落盘策略。
        let tmp_path = path.with_extension("tmp");
        std::fs::write(&tmp_path, &bytes)?;
        std::fs::rename(&tmp_path, &path)?;
        self.cache.insert(hash, node.clone());
        Ok(())
    }

    /// 反序列化还原：从根哈希递归重建完整 `serde_json::Value`。
    pub fn reconstruct(&mut self, hash: NodeHash) -> std::io::Result<Value> {
        let node = self.load(hash)?;
        Ok(match node {
            MerkleNode::Null => Value::Null,
            MerkleNode::Bool(b) => Value::Bool(b),
            MerkleNode::Number { canonical_bytes } => Value::Number(decanonicalize_number(&canonical_bytes)),
            MerkleNode::String(s) => Value::String(s),
            MerkleNode::Array { children } => {
                let mut arr = Vec::with_capacity(children.len());
                for child_hash in children {
                    arr.push(self.reconstruct(child_hash)?);
                }
                Value::Array(arr)
            }
            MerkleNode::Object { entries } => {
                let mut map = serde_json::Map::new();
                for (k, val_hash) in entries {
                    map.insert(k, self.reconstruct(val_hash)?);
                }
                Value::Object(map)
            }
        })
    }

    fn load(&mut self, hash: NodeHash) -> std::io::Result<MerkleNode> {
        if let Some(n) = self.cache.get(&hash) {
            return Ok(n.clone());
        }
        let path = hash.shard_path(&self.root_dir);
        let bytes = std::fs::read(&path)?;
        let obj: CasObject = bincode::deserialize(&bytes)
            .map_err(|e| std::io::Error::new(std::io::ErrorKind::InvalidData, e))?;
        self.cache.insert(hash, obj.node.clone());
        Ok(obj.node)
    }
}

fn canonicalize_number(n: &serde_json::Number) -> Vec<u8> {
    if let Some(i) = n.as_i64() {
        let mut v = vec![0u8]; // 判别符：整数
        v.extend_from_slice(&i.to_be_bytes());
        v
    } else {
        let f = n.as_f64().unwrap_or(0.0);
        let mut v = vec![1u8]; // 判别符：浮点数
        v.extend_from_slice(&f.to_be_bytes());
        v
    }
}

fn decanonicalize_number(bytes: &[u8]) -> serde_json::Number {
    match bytes[0] {
        0 => serde_json::Number::from(i64::from_be_bytes(bytes[1..9].try_into().unwrap())),
        _ => serde_json::Number::from_f64(f64::from_be_bytes(bytes[1..9].try_into().unwrap()))
            .unwrap_or_else(|| serde_json::Number::from(0)),
    }
}
```

### 1.4 单字段变更 O(N) → O(log N) 的复杂度证明

设一棵近似平衡的 JSON AST 树高为 `h ≈ log_b(N)`（`b` 为平均分支因子，`N` 为节点总数）。当仅有一个叶子节点的值发生变更时：

1. 该叶子的哈希 `H(leaf)` 改变。
2. 根据 1.1 节的递归定义，其**直接父节点**的哈希由子哈希列表拼接计算得出，子哈希变化 ⇒ 父哈希必然改变，因此变更沿"从叶子到根"的唯一路径逐层传播。
3. 路径上每一层只有**一个**节点的哈希改变（因为其余兄弟子树的哈希未变，会直接复用缓存/磁盘上已存在的对象，`write_if_absent` 检测到 `path.exists()` 后立即返回，不产生新 I/O）。
4. 因此实际发生的**新增磁盘写入数** = 路径长度 = 树高 `h = O(log N)`（对平衡或近似平衡的真实世界 JSON 报文而言），而非重写整棵树的 `O(N)`。

对比传统方案（每次快照整体序列化落盘，`.snap.json` 作为单一大文件）：单字段变更时 Git diff/存储都是 `O(N)`（整份文件字节级不同，Git 的 delta 压缩虽能部分缓解，但仍需扫描整份文件计算 delta，且新文件仍需完整落盘一次）。CAS 方案下同样的变更只产生 `O(log N)` 个新 CAS 对象文件，历史上所有未变的子树在物理磁盘和 Git 历史中均为同一 blob，天然去重——这正是 90%+ 体积削减的来源，尤其对"响应体绝大部分字段稳定、仅个别字段随版本迭代变化"的典型 API 场景效果显著。

## 模块二：Cranelift JIT 即时规则编译器

### 2.1 设计原理：从解释执行到机器码降解

当前 RFC-001 中 `MaskContext` 对每个叶子节点的处理是**解释执行**：运行时遍历 `Vec<PathSegment>`，逐段比较字符串/索引，本质是一个树形状态机的软件模拟，每次比较都要经过分支预测、字符串比较、Vec 索引边界检查等解释开销。当规则集在配置加载时就已**完全确定**（不会在单次 `test`/`record` 运行期间动态变化）时,这是一个典型的"运行时常量"场景——可以在规则加载阶段一次性将其**编译**为原生机器码，把"路径匹配"这个纯粹的控制流问题从"每次遍历都重新解释"变成"CPU 直接执行几条 `cmp`/`je` 指令"。

设计原理：把每条 `CustomMaskRule.json_path` 的路径段序列，降解为一棵路径前缀树（Trie），再把这棵 Trie 的每一层节点映射为 Cranelift IR 中的一个 Basic Block：进入某一层时，先将"当前路径段的哈希值"（预先对路径段字符串做 FNV-1a 哈希，避免在生成的机器码中比较变长字符串）与该层 Trie 节点的所有分支哈希逐一用 `icmp eq` 比较，命中则跳转（`brif`）到子层对应的 Basic Block，全部不命中则跳转到"未匹配"终止块。整条路径匹配到叶子层即代表命中一条规则，返回该规则在规则表中的索引（`iconst` 编码为立即数返回值）。

### 2.2 `CraneliftRuleEngine` 完整实现

```rust
use cranelift::prelude::*;
use cranelift_jit::{JITBuilder, JITModule};
use cranelift_module::{Linkage, Module};
use std::collections::HashMap;

/// 编译后规则匹配函数的签名：输入指向"路径段哈希数组"的指针与其长度，
/// 输出匹配到的规则索引；未匹配时返回 u32::MAX 作为哨兵值。
pub type CompiledMatchFn = unsafe extern "C" fn(*const u64, u64) -> u32;

pub struct CraneliftRuleEngine {
    module: JITModule,
    /// 编译产物的函数指针缓存，key 为规则集的内容哈希（规则集不变时复用编译结果）。
    compiled: HashMap<u64, CompiledMatchFn>,
}

/// 路径前缀树的中间表示，编译前的规则组织形式。
struct PathTrieNode {
    /// 子节点：路径段的 FNV-1a 哈希 → 子 Trie 节点。
    children: HashMap<u64, PathTrieNode>,
    /// 若此节点是某条完整规则路径的终点，记录其在原始规则表中的索引。
    rule_index: Option<u32>,
}

fn fnv1a_hash(s: &str) -> u64 {
    const FNV_OFFSET: u64 = 0xcbf29ce484222325;
    const FNV_PRIME: u64 = 0x100000001b3;
    let mut hash = FNV_OFFSET;
    for byte in s.as_bytes() {
        hash ^= byte as u64;
        hash = hash.wrapping_mul(FNV_PRIME);
    }
    hash
}

impl CraneliftRuleEngine {
    pub fn new() -> Self {
        let builder = JITBuilder::new(cranelift_module::default_libcall_names())
            .expect("failed to create JIT builder for target ISA");
        let module = JITModule::new(builder);
        Self { module, compiled: HashMap::new() }
    }

    /// 将一组 JSONPath 规则字符串（如 "$.data.token"）编译为一个原生函数指针。
    pub fn compile_rules(&mut self, paths: &[String]) -> CompiledMatchFn {
        // 1. 构建路径前缀树
        let mut root = PathTrieNode { children: HashMap::new(), rule_index: None };
        for (idx, path) in paths.iter().enumerate() {
            let segments: Vec<&str> = path.trim_start_matches('$').split('.').filter(|s| !s.is_empty()).collect();
            let mut node = &mut root;
            for seg in segments {
                let h = fnv1a_hash(seg);
                node = node.children.entry(h).or_insert_with(|| PathTrieNode {
                    children: HashMap::new(),
                    rule_index: None,
                });
            }
            node.rule_index = Some(idx as u32);
        }

        // 2. 在 Cranelift IR 中生成函数
        let mut ctx = self.module.make_context();
        let mut fn_builder_ctx = FunctionBuilderContext::new();

        let mut sig = self.module.make_signature();
        sig.params.push(AbiParam::new(types::I64)); // *const u64 数组指针
        sig.params.push(AbiParam::new(types::I64)); // 数组长度
        sig.returns.push(AbiParam::new(types::I32)); // 匹配到的规则索引

        let func_id = self.module
            .declare_function("rule_match", Linkage::Export, &sig)
            .expect("failed to declare JIT function");
        ctx.func.signature = sig;

        {
            let mut builder = FunctionBuilder::new(&mut ctx.func, &mut fn_builder_ctx);
            let entry_block = builder.create_block();
            builder.append_block_params_for_function_params(entry_block);
            builder.switch_to_block(entry_block);
            builder.seal_block(entry_block);

            let ptr_val = builder.block_params(entry_block)[0];
            let len_val = builder.block_params(entry_block)[1];

            let no_match_block = builder.create_block();

            // 递归为 Trie 的每一层生成 Basic Block 链
            emit_trie_level(&mut builder, &root, ptr_val, len_val, 0, no_match_block);

            builder.switch_to_block(no_match_block);
            builder.seal_block(no_match_block);
            let sentinel = builder.ins().iconst(types::I32, u32::MAX as i64);
            builder.ins().return_(&[sentinel]);

            builder.finalize();
        }

        // 3. 编译并链接为可执行机器码
        self.module.define_function(func_id, &mut ctx).expect("JIT compilation failed");
        self.module.clear_context(&mut ctx);
        self.module.finalize_definitions().expect("JIT linking failed");

        let code_ptr = self.module.get_finalized_function(func_id);
        let compiled_fn: CompiledMatchFn = unsafe { std::mem::transmute(code_ptr) };

        let rules_hash = compute_ruleset_hash(paths);
        self.compiled.insert(rules_hash, compiled_fn);
        compiled_fn
    }
}

/// 递归生成 Trie 某一层对应的 IR：依次对每个子分支做 `icmp eq` 判断，
/// 命中则 `brif` 跳转进入该子分支对应的下一层 Basic Block。
fn emit_trie_level(
    builder: &mut FunctionBuilder,
    node: &PathTrieNode,
    ptr_val: Value,
    len_val: Value,
    depth: i64,
    no_match_block: Block,
) {
    if let Some(idx) = node.rule_index {
        if node.children.is_empty() {
            let ret = builder.ins().iconst(types::I32, idx as i64);
            builder.ins().return_(&[ret]);
            return;
        }
    }

    // 边界检查：若当前深度已超出输入路径长度，直接判定未匹配。
    let depth_val = builder.ins().iconst(types::I64, depth);
    let in_bounds = builder.ins().icmp(IntCC::UnsignedLessThan, depth_val, len_val);
    let bounds_ok_block = builder.create_block();
    builder.ins().brif(in_bounds, bounds_ok_block, &[], no_match_block, &[]);
    builder.switch_to_block(bounds_ok_block);
    builder.seal_block(bounds_ok_block);

    // 从输入数组中加载当前深度的路径段哈希：*(ptr + depth * 8)
    let offset = builder.ins().iconst(types::I64, depth * 8);
    let addr = builder.ins().iadd(ptr_val, offset);
    let seg_hash = builder.ins().load(types::I64, MemFlags::new(), addr, 0);

    for (&child_hash, child_node) in node.children.iter() {
        let const_hash = builder.ins().iconst(types::I64, child_hash as i64);
        let is_eq = builder.ins().icmp(IntCC::Equal, seg_hash, const_hash);

        let match_block = builder.create_block();
        let next_check_block = builder.create_block();
        builder.ins().brif(is_eq, match_block, &[], next_check_block, &[]);

        builder.switch_to_block(match_block);
        builder.seal_block(match_block);
        emit_trie_level(builder, child_node, ptr_val, len_val, depth + 1, no_match_block);

        builder.switch_to_block(next_check_block);
        builder.seal_block(next_check_block);
    }

    // 该层所有分支哈希均未命中，跳转至未匹配终止块。
    builder.ins().jump(no_match_block, &[]);
}

fn compute_ruleset_hash(paths: &[String]) -> u64 {
    let mut h = 0xcbf29ce484222325u64;
    for p in paths {
        for b in p.as_bytes() {
            h ^= *b as u64;
            h = h.wrapping_mul(0x100000001b3);
        }
    }
    h
}
```

> **适用边界声明：** 本模块面向的场景是——运维/研发团队在**自己拥有管理权限的**集群节点上，对**自身运维的微服务**进行流量镜像与快照录制，用于回归测试与契约漂移检测，属于标准的可观测性（observability）基础设施范畴，与 Cilium、Pixie、Hubble 等开源项目的技术路线一致。以下实现假定运行环境已获得部署方的合法授权（CAP_BPF / CAP_NET_ADMIN 权限、集群管理员批准）。

### 3.1 内核态 eBPF 程序（挂载于 TC ingress/egress）

```c
// src/ebpf/traffic_capture.bpf.c
// 编译目标：BPF 字节码，通过 clang -target bpf 编译，libbpf CO-RE 方式加载
#include <linux/bpf.h>
#include <linux/if_ether.h>
#include <linux/ip.h>
#include <linux/tcp.h>
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_endian.h>

#define MAX_PAYLOAD_CAPTURE 4096

/* 通过 BPF_MAP_TYPE_RINGBUF 实现内核到用户态的无锁高性能环形缓冲区，
   相比传统 BPF_MAP_TYPE_PERF_EVENT_ARRAY，RINGBUF 避免了每 CPU 独立缓冲区
   导致的事件乱序与内存浪费，且支持变长记录，天然适合变长 HTTP 报文捕获。 */
struct {
    __uint(type, BPF_MAP_TYPE_RINGBUF);
    __uint(max_entries, 1 << 24); /* 16MB 环形缓冲区 */
} traffic_events SEC(".maps");

struct captured_packet {
    __u32 src_ip;
    __u32 dst_ip;
    __u16 src_port;
    __u16 dst_port;
    __u32 payload_len;
    __u8  payload[MAX_PAYLOAD_CAPTURE];
};

SEC("tc")
int capture_egress(struct __sk_buff *skb) {
    void *data_end = (void *)(long)skb->data_end;
    void *data = (void *)(long)skb->data;

    struct ethhdr *eth = data;
    if ((void *)(eth + 1) > data_end)
        return TC_ACT_OK; /* 报文过短，直接放行，不参与捕获 */

    if (bpf_ntohs(eth->h_proto) != ETH_P_IP)
        return TC_ACT_OK;

    struct iphdr *ip = (void *)(eth + 1);
    if ((void *)(ip + 1) > data_end)
        return TC_ACT_OK;

    if (ip->protocol != IPPROTO_TCP)
        return TC_ACT_OK;

    struct tcphdr *tcp = (void *)ip + (ip->ihl * 4);
    if ((void *)(tcp + 1) > data_end)
        return TC_ACT_OK;

    /* 仅捕获 HTTP 明文流量常见端口，生产部署中通过用户态配置动态更新
       端口过滤 map（BPF_MAP_TYPE_HASH<u16, u8>），此处为简化示意固定端口。 */
    __u16 dst_port = bpf_ntohs(tcp->dest);
    if (dst_port != 80 && dst_port != 8080 && dst_port != 3000)
        return TC_ACT_OK;

    void *payload = (void *)tcp + (tcp->doff * 4);
    __u32 payload_len = (__u32)(data_end - payload);
    if (payload <= data_end && payload_len > 0) {
        struct captured_packet *evt;
        __u32 cap_len = payload_len > MAX_PAYLOAD_CAPTURE ? MAX_PAYLOAD_CAPTURE : payload_len;

        evt = bpf_ringbuf_reserve(&traffic_events, sizeof(*evt), 0);
        if (!evt)
            return TC_ACT_OK; /* 环形缓冲区已满，丢弃本次捕获但不影响正常转发 */

        evt->src_ip = ip->saddr;
        evt->dst_ip = ip->daddr;
        evt->src_port = bpf_ntohs(tcp->source);
        evt->dst_port = dst_port;
        evt->payload_len = cap_len;

        /* bpf_probe_read_kernel 需要编译期已知长度，此处以固定上限逐块拷贝，
           验证器（verifier）要求所有内存访问长度在编译期可静态证明有界。 */
        if (payload + cap_len <= data_end) {
            bpf_probe_read_kernel(&evt->payload, cap_len, payload);
        }

        bpf_ringbuf_submit(evt, 0);
    }

    return TC_ACT_OK; /* 始终放行，本程序只做旁路捕获，不影响正常流量转发 */
}

char _license[] SEC("license") = "GPL";
```

### 3.2 用户态 Rust 消费者（基于 `aya`）

```rust
// src/ebpf_consumer/mod.rs
use aya::maps::RingBuf;
use aya::programs::{tc, SchedClassifier, TcAttachType};
use aya::{Ebpf, EbpfLoader};
use std::convert::TryInto;
use tokio::io::unix::AsyncFd;

#[repr(C)]
struct CapturedPacket {
    src_ip: u32,
    dst_ip: u32,
    src_port: u16,
    dst_port: u16,
    payload_len: u32,
    payload: [u8; 4096],
}

/// 加载 eBPF 字节码、挂载到指定网卡的 TC egress 钩子，并启动零拷贝消费循环。
pub async fn start_capture(
    iface: &str,
    mask_pipeline_tx: tokio::sync::mpsc::Sender<serde_json::Value>,
) -> anyhow::Result<()> {
    let mut ebpf = EbpfLoader::new()
        .load(include_bytes_aligned!("../../target/bpf/traffic_capture.bpf.o"))?;

    let program: &mut SchedClassifier = ebpf
        .program_mut("capture_egress")
        .expect("eBPF object missing capture_egress program")
        .try_into()?;
    program.load()?;

    tc::qdisc_add_clsact(iface)?;
    program.attach(iface, TcAttachType::Egress)?;

    let ring_map = ebpf.take_map("traffic_events").expect("ringbuf map not found");
    let mut ring_buf = RingBuf::try_from(ring_map)?;
    let mut async_fd = AsyncFd::new(ring_buf)?;

    loop {
        let mut guard = async_fd.readable_mut().await?;
        let ring = guard.get_inner_mut();

        // 零拷贝读取：直接从内核共享内存映射区解释字节，不额外拷贝到堆。
        while let Some(item) = ring.next() {
            let raw: &[u8] = &item;
            if raw.len() < std::mem::size_of::<CapturedPacket>() {
                continue;
            }
            let pkt: &CapturedPacket = unsafe { &*(raw.as_ptr() as *const CapturedPacket) };
            let payload_slice = &pkt.payload[..pkt.payload_len.min(4096) as usize];

            // 尝试从捕获的 TCP payload 中剥离 HTTP 头，提取 JSON body。
            if let Some(json_body) = extract_http_json_body(payload_slice) {
                if let Ok(value) = serde_json::from_slice::<serde_json::Value>(json_body) {
                    // 送入既有的脱敏管道（复用模块一/RFC-001 的 masker），
                    // 后续流程与手动配置 endpoint 捕获的响应完全一致。
                    let _ = mask_pipeline_tx.send(value).await;
                }
            }
        }
        guard.clear_ready();
    }
}

/// 在原始 TCP payload 中定位 "\r\n\r\n" 分隔符后的 HTTP body 起始位置。
fn extract_http_json_body(raw: &[u8]) -> Option<&[u8]> {
    let sep = b"\r\n\r\n";
    raw.windows(sep.len())
        .position(|w| w == sep)
        .map(|pos| &raw[pos + sep.len()..])
        .filter(|body| !body.is_empty())
}
```

### 4.1 `HttpContext` / `RootContext` 状态机

```rust
use proxy_wasm::traits::*;
use proxy_wasm::types::*;
use std::collections::HashMap;

proxy_wasm::main! {{
    proxy_wasm::set_log_level(LogLevel::Info);
    proxy_wasm::set_root_context(|_| -> Box<dyn RootContext> {
        Box::new(ApiSnapShadowRoot { config: None })
    });

/// Root 级别上下文：每个 Envoy worker 线程一份，负责插件级配置解析
/// 与跨请求共享的规则集（复用模块二编译产物）。
struct ApiSnapShadowRoot {
    config: Option<ShadowCompareConfig>,
}

struct ShadowCompareConfig {
    baseline_upstream_cluster: String,
    candidate_upstream_cluster: String,
    drift_metric_id: u32,
}

impl Context for ApiSnapShadowRoot {}

impl RootContext for ApiSnapShadowRoot {
    fn on_configure(&mut self, _plugin_configuration_size: usize) -> bool {
        if let Some(raw) = self.get_plugin_configuration() {
            if let Ok(cfg) = serde_json::from_slice::<ShadowCompareRawConfig>(&raw) {
                let drift_metric_id = self.define_metric(
                    MetricType::Counter,
                    "apisnap_shadow_drift_total",
                );
                self.config = Some(ShadowCompareConfig {
                    baseline_upstream_cluster: cfg.baseline_cluster,
                    candidate_upstream_cluster: cfg.candidate_cluster,
                    drift_metric_id,
                });
            }
        }
        true
    }

    fn create_http_context(&self, context_id: u32) -> Option<Box<dyn HttpContext>> {
        self.config.as_ref().map(|cfg| {
            Box::new(ApiSnapShadowHttp {
                context_id,
                drift_metric_id: cfg.drift_metric_id,

                candidate_body: Vec::new(),
                streaming_complete: false,
            }) as Box<dyn HttpContext>
        })
    }

    fn get_type(&self) -> Option<ContextType> {
        Some(ContextType::HttpContext)
    }
}

#[derive(serde::Deserialize)]
struct ShadowCompareRawConfig {
    baseline_cluster: String,
    candidate_cluster: String,
}

/// HTTP 请求级上下文：流式接收 baseline / candidate 双路响应体，
/// 在响应体接收完成时触发实时 AST 比对。
struct ApiSnapShadowHttp {
    context_id: u32,
    drift_metric_id: u32,
    baseline_body: Vec<u8>,
    candidate_body: Vec<u8>,
    streaming_complete: bool,
}

impl Context for ApiSnapShadowHttp {}

impl HttpContext for ApiSnapShadowHttp {
    /// 流式接收响应体分块：Envoy 会多次调用本回调，每次传入一段 body chunk，
    /// `end_of_stream` 为真时代表这是最后一块。累积分块而非等待整体缓冲，
    /// 使得插件对超大响应体也能以恒定的单块内存开销处理。
    fn on_http_response_body(&mut self, body_size: usize, end_of_stream: bool) -> Action {
        if let Some(chunk) = self.get_http_response_body(0, body_size) {
            // 通过响应头 x-apisnap-shadow-role 区分该次响应来自 baseline 还是 candidate 集群，
            // 该头由前置的流量镜像（mirror_policy）配置在请求侧一并注入。
            let role = self
                .get_http_response_header("x-apisnap-shadow-role")
                .unwrap_or_default();
            if role == "candidate" {
                self.candidate_body.extend_from_slice(&chunk);
            } else {
                self.baseline_body.extend_from_slice(&chunk);
            }
        }

        if end_of_stream {
            self.streaming_complete = true;
            self.perform_drift_check();
        }

        Action::Continue
    }
}

impl ApiSnapShadowHttp {
    /// 使用 SIMD-JSON 对累积完成的双路响应体做一次实时 AST 比对；
    /// 复用 RFC-001 Algorithm B 的比对语义（对象按 Set 比较、数组按序比较），
    /// 但输出简化为"是否存在契约漂移"的布尔判定，避免在 Wasm 沙箱内
    /// 构造完整 DiffReport 带来的额外分配开销（Wasm 线性内存增长成本较高）。
    fn perform_drift_check(&mut self) {
        if self.baseline_body.is_empty() || self.candidate_body.is_empty() {
            return; // 双路未同时到达，无法比对，静默跳过（不计入漂移指标）
        }

        let mut baseline_buf = self.baseline_body.clone();
        let mut candidate_buf = self.candidate_body.clone();

        let baseline_parsed = simd_json::to_borrowed_value(&mut baseline_buf);
        let candidate_parsed = simd_json::to_borrowed_value(&mut candidate_buf);

        match (baseline_parsed, candidate_parsed) {
            (Ok(base_val), Ok(cand_val)) => {
                if structurally_drifted(&base_val, &cand_val) {
                    self.increment_metric(self.drift_metric_id, 1).ok();
                    self.log_drift_event();
                }
            }
            _ => {
                // 任一路解析失败本身就是一种漂移信号（例如 candidate 返回了非法 JSON）。
                self.increment_metric(self.drift_metric_id, 1).ok();
            }
        }
    }

    fn log_drift_event(&self) {
        proxy_wasm::hostcalls::log(
            LogLevel::Warn,
            &format!(
                "[apisnap-shadow] contract drift detected on context_id={}",
                self.context_id
            ),
        )
        .ok();
    }
}

/// 简化版结构漂移检测：仅比较 Object 的键集合与 Array 长度是否一致，
/// 不逐叶子比较值本身（值级比对留给异步旁路的完整 DiffReport 生成，
/// 以保证 Wasm 沙箱内单请求开销 < 1ms 的目标）。
fn structurally_drifted(a: &simd_json::BorrowedValue, b: &simd_json::BorrowedValue) -> bool {
    use simd_json::ValueAccess;
    match (a.as_object(), b.as_object()) {
        (Some(ao), Some(bo)) => {
            let ak: std::collections::BTreeSet<_> = ao.keys().collect();
            let bk: std::collections::BTreeSet<_> = bo.keys().collect();
            if ak != bk {
                return true;
            }
            ao.iter().any(|(k, av)| {
                bo.get(k.as_ref()).map_or(true, |bv| structurally_drifted(av, bv))
            })
        }
        (Some(_), None) | (None, Some(_)) => true,
        (None, None) => {
            if let (Some(aa), Some(ba)) = (a.as_array(), b.as_array()) {
                aa.len() != ba.len()
                    || aa.iter().zip(ba.iter()).any(|(x, y)| structurally_drifted(x, y))
            } else {
                false
            }
        }
    }
}
```

## 模块五：全链路 OpenTelemetry 分布式追踪注入与 APM 根因直连

### 5.1 W3C Trace Context 规范的严格实现

```rust
use rand::RngCore;

/// W3C Trace Context `traceparent` 头的完整二进制表示。
/// 规范：https://www.w3.org/TR/trace-context/
#[derive(Debug, Clone, Copy)]
pub struct TraceContext {
    pub version: u8,       // 固定为 0x00（当前唯一定义版本）
    pub trace_id: [u8; 16], // 128 位，全局唯一标识一条完整调用链
    pub span_id: [u8; 8],   // 64 位，标识链路中的单个操作片段
    pub trace_flags: u8,    // 目前仅定义 bit0 = sampled
}

impl TraceContext {
    /// 生成一个新的根 Trace Context（用于 ApiSnap 主动发起的请求，
    /// 当上游未传入 traceparent 时，本引擎作为链路起点）。
    pub fn new_root() -> Self {
        let mut rng = rand::thread_rng();
        let mut trace_id = [0u8; 16];
        let mut span_id = [0u8; 8];
        rng.fill_bytes(&mut trace_id);
        rng.fill_bytes(&mut span_id);

        // 规范要求 trace_id 与 span_id 不得全为零字节。
        if trace_id.iter().all(|&b| b == 0) {
            trace_id[0] = 1;
        }
        if span_id.iter().all(|&b| b == 0) {
            span_id[0] = 1;
        }

        TraceContext {
            version: 0x00,
            trace_id,
            span_id,
            trace_flags: 0x01, // sampled = true，确保回归失败链路必定被后端保留
        }
    }

    /// 从现有 trace_id 派生一个新的子 span（用于在既有调用链中标记本次校验动作）。
    pub fn new_child_span(&self) -> Self {
        let mut rng = rand::thread_rng();
        let mut span_id = [0u8; 8];
        rng.fill_bytes(&mut span_id);
        if span_id.iter().all(|&b| b == 0) {
            span_id[0] = 1;
        }
        TraceContext {
            version: self.version,
            trace_id: self.trace_id,
            span_id,
            trace_flags: self.trace_flags,
        }
    }

    /// 序列化为 `traceparent` 头的规范字符串形式：
    /// "{version}-{trace_id}-{span_id}-{trace_flags}"，全小写十六进制。
    pub fn to_traceparent_header(&self) -> String {
        format!(
            "{:02x}-{}-{}-{:02x}",
            self.version,
            hex::encode(self.trace_id),
            hex::encode(self.span_id),
            self.trace_flags
        )
    }

    /// 严格按规范解析入站 `traceparent` 头；任何字段长度/格式不合规
    /// 均返回 `None`，调用方应在解析失败时退化为 `new_root()`。
    pub fn parse(header: &str) -> Option<Self> {
        let parts: Vec<&str> = header.split('-').collect();
        if parts.len() != 4 {
            return None;
        }
        let version = u8::from_str_radix(parts[0], 16).ok()?;
        if parts[0].len() != 2 || version == 0xff {
            return None; // 0xff 版本号在规范中保留，禁止使用
        }
        if parts[1].len() != 32 || parts[2].len() != 16 || parts[3].len() != 2 {
            return None;
        }
        let trace_id_vec = hex::decode(parts[1]).ok()?;
        let span_id_vec = hex::decode(parts[2]).ok()?;
        let trace_flags = u8::from_str_radix(parts[3], 16).ok()?;

        let mut trace_id = [0u8; 16];
        let mut span_id = [0u8; 8];
        trace_id.copy_from_slice(&trace_id_vec);
        span_id.copy_from_slice(&span_id_vec);

        if trace_id.iter().all(|&b| b == 0) || span_id.iter().all(|&b| b == 0) {
            return None; // 规范禁止全零 trace_id / span_id
        }

        Some(TraceContext { version, trace_id, span_id, trace_flags })
    }
}
```

### 5.2 请求头注入器与差异发现后的 APM 深度链接合成

```rust
use reqwest::RequestBuilder;

/// 在 ApiSnap 发起的每个请求上注入 `traceparent` 头，使得本次快照测试
/// 天然成为目标微服务调用链的一部分，后端 APM 能够采集到完整的下游调用。
pub fn inject_trace_header(builder: RequestBuilder, ctx: &TraceContext) -> RequestBuilder {

}

/// 差异发现后的根因直连：将本次比对失败关联的 trace_id 合成为
/// 目标 APM 后端的深度定位 URL，直接嵌入 DiffReport 供人工点击跳转。
pub enum ApmBackend {
    Jaeger { base_url: String },
    DatadogApm { site: String }, // 例如 "datadoghq.com"
}

impl ApmBackend {
    pub fn build_trace_link(&self, ctx: &TraceContext) -> String {
        let trace_id_hex = hex::encode(ctx.trace_id);
        match self {
            ApmBackend::Jaeger { base_url } => {
                format!("{}/trace/{}", base_url.trim_end_matches('/'), trace_id_hex)
            }
            ApmBackend::DatadogApm { site } => {
                // Datadog APM 要求 trace_id 以十进制表示其低 64 位（dd_trace_id）。
                let low_64 = u64::from_be_bytes(ctx.trace_id[8..16].try_into().unwrap());
                format!(
                    "https://app.{}/apm/trace/{}",
                    site, low_64
                )
            }
        }
    }
}
```
